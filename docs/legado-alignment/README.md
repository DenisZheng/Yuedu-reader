## 必须先统一的概念

1. **书源不等于文本源。** `bookSourceType` 可以是文本、音频、图片、文件或视频。
2. **Legado 订阅源不等于标准 RSS Feed。** 它还能是规则抓取站点、交互网页、图片或视频入口。
3. **有播放器不等于源可用。** 前面的源上下文、请求、解析、解密、分页和状态写回都需要正确。
4. **`java` 不是在所有地方都绑定同一对象。** URL、提取规则、源脚本、页面 JS 分别有自己的桥接对象。
5. **源级变量、请求变量、书籍/章节/文章变量、通用 cache 不是同一份状态。** 错误合并会造成丢状态或串源。
6. **数据类型数字不能混用。** `BookSourceType`、`BookType`、`SourceType`、RSS `type` 属于不同域，见架构文档。
7. **字段存在不等于被执行。** 必须追到消费点；代码注释与旧 README 也可能落后于实现。

## 后续对齐的工作方法

已完成 Q1–Q9 产品决策，形成 [最终方案 v2.0](development-plan.md) 和 [执行计划](implementation-plan.md)：首期独立本地 Fork、RSS 闭环、按 Android 源配置运行规则网页、分层代表源验收。业务术语见根目录 [CONTEXT.md](../../CONTEXT.md)，关键决策见 `docs/adr/`。整体执行确认与各阶段状态记录在执行计划；方案不等于实现完成证据。

每个任务填写下面的小型契约，不需要每次重新审计全仓库：

```text
目标行为：
Android 基准 commit：
输入：源配置 + 请求/响应 fixture + 初始状态
入口及调用链：
输出：结果、顺序、URL、媒体数据、错误
状态读写：源 / 操作 / 书籍 / 章节 / RSS 文章
副作用与权限：网络、持久化、打开网页、用户操作
缓存命中 / 网络 / 分页 / 重试或取消时的行为：
iOS 接入点：
固定输入的对照结果：
真实源/设备验收结果：
尚未覆盖的分支：
```

推荐顺序：固定响应的离线契约测试 → 应用内路由/状态测试 → 授权的真实源网络与播放验收。站点不可达、账号状态、源过期与程序不兼容分开记录。

### 针对现有样本的优先级

先补 RSS 的源会话、规则回调、`singleUrl` 打开优先级、HTML 媒体、注入与分页；再逐类型验收书源。样本中没有 `mainJs` 或 RSS type=1/2，不代表这些基准能力不需要对齐，而是需要独立 fixture，不应抢占已确认故障路径的排查顺序。

## 边界与维护

- **事实层**：文档描述固定基准的源码行为；**建议层**：iOS 接入与测试建议，不表示已实现。
- 本轮读取了构建配置、核心模型和调用链，以及部分测试源码；没有构建 Android/iOS，没有执行真实源脚本，也没有重新进行网络/播放测试。此前离线导入实验的范围单独记录在真实源包审计。
- 核心书源/RSS 路径追到了执行和状态层；备份、自动任务、TTS、Web/MCP 等在这里主要提供归属与入口，不能当作完整子系统认证。
- 保留 SwiftUI/CoreText、现有 iOS 服务与阅读位置模型；不照搬 Android 的全局单例、阻塞调用、Room 主线程查询或安全例外。
- 源脚本和网页内容始终是外部输入。网络、文件、Cookie、跨 App 导航等权限需要 iOS 自身的清晰边界，不能为了兼容把页面桥接成无限制执行环境。
- 更新 Android 基准时，先核对这四篇引用的文件及契约，再更新 commit；不要只改页首版本号。
- 原始源包可能有登录/私有请求配置。文档只保留类型、数量和必要的定位编号，不复制完整脚本、请求头或凭据。
- 本地两仓库分别使用 MPL-2.0 / GPL-3.0 根许可证。对齐行为与复制源码是两件事；源码移植和公开分发前另做许可与品牌审查。
