## 命令与证据

工具链仍由 `scripts/sim.sh xcode` 解析，手机从 `devicectl list devices --json-output` 的唯一物理设备解析；个人团队ID和设备ID不写入文档或仓库。

```bash
export DEVELOPER_DIR="$(bash scripts/sim.sh xcode)"
# SOURCE为15a29143的独立worktree；DEVICE由本机设备列表选择。
cd "$SOURCE"
xcodebuild -project Yuedu-Reader.xcodeproj -scheme Reader-Fork-Dev -configuration Debug \
  -destination "id=$DEVICE" -xcconfig "$DEVICE_CONFIG" \
  -derivedDataPath "$DEVICE_DERIVED_DATA" build-for-testing
xcrun devicectl device install app --device "$DEVICE" "$APP"
xcrun devicectl device process launch --device "$DEVICE" dev.denis.readerfork.dev -- -no-official-modules
# 将validate_reader_fork_s6.sh的s6数组转换为逐suite的-only-testing参数。
YUEDU_SCHEME=Reader-Fork-Dev YUEDU_DEST="id=$DEVICE" \
  bash scripts/xctest.sh -l "$EVIDENCE/device-s6.log" -- \
  -xcconfig "$DEVICE_CONFIG" -derivedDataPath "$DEVICE_DERIVED_DATA" \
  -resultBundlePath "$EVIDENCE/device-s6.xcresult" "${SUITE_ARGS[@]}"
```

本次证据根目录：`/tmp/readerfork-device-current.DekGzG/`。

- `build.log`、`install.log`、`launch.json`：构建、安装、启动。
- `device-s6.log`、`device-s6.xcresult`：最终测试日志及完整结果。中途Swift Testing的78项/16 suites不是完整数量；最终xcresult为101项/20 suites，包含XCTest媒体用例。
- `device-s6-summary.json`、`device-s6-tests.json`、`verified-device-summary.json`：最终结果、逐用例树和20个suite/关键媒体用例的核对。
- `installed-app.json`、`final-launch.json`：安装后与测试后重新打开正常App的核对。

初次启动命令未用`--`分隔App参数，`-no-official-modules`被devicectl当成自身选项，退出64；安装已成功，仅修正启动命令，未重装或修改App。结果核对脚本也先后误用了不存在的HLS方法名及猜测的媒体用例数量；改为核对真实四个播放方法和20个suite后通过，未改测试或重跑以消除失败。
