## 1. 总体结论

**架构与安全设计质量高，RSS 行为对齐程度远超上游，主体交付成立。** 请求票据/撤销、网页动作权限分级、loopback 媒体能力代理、WebDAV 版本化备份等核心机制设计严谨；阶段文档诚实（`s8-acceptance.md` 明确「整体尚未通过」并保留失败证据）。

**但当前不宜按「S0–S8 全部完成」收尾**，需要优先处理三件事：

1. **上游已落后 62 个提交，试合并有 28 个冲突文件**，含 RSS 运行时依赖的规则引擎与 JS 桥（P0-1）。
2. **RSS 深链仍进书源导入器，且会把 RSS JSON「成功」解码成空书源**（P0-2，两次审查均提出，未修）。
3. **S8 按项目自己的记录是「自动回归通过、人工待验」**，iframe 真实播放、受限登录、iOS 17、正式签名等未闭合（P1-1）。

## 3. 问题详述

### P0-1（高）落后上游 62 提交，试合并 28 冲突

**本地实测**：`git fetch upstream` 后 `HEAD..upstream/main` 为 62、`upstream/main..HEAD` 为 22；`git merge --no-commit upstream/main` 产生 28 个冲突路径，已 `merge --abort`，工作区恢复原状。与 Claude 版清单逐项一致。

冲突集中于 fork RSS 运行时所依赖的底层：

- 规则引擎与 JS：`ModernRuleEngine`、`ModernParserBridge`、`JSCoreEngine`、`LegadoJSBridge`、`LegadoSourceBridge`、`LegadoCacheBridge`、`CookieStore`
- 书源核心：`BookSourceFetcher`、`BookSourceSession`、`SharedImportQueueDrainer`
- RSS：`LegadoRSSScraper`、`RSSListView`、`RSSPageDecodingTests`
- 应用与阅读器：`yuedu_appApp`、`RootTabCustomization(View)`、`VideoPlaybackController`、`TTSRoleCastView`、`ReaderViewportReporting`
- 删改冲突（fork 已删除、上游仍在改）：`Services/Account/AuthRoutePolicy.swift`、`GatewayAPIClient.swift`
- 五语言 `Localizable.strings`

上游同期在同一批文件有实质修复（源正则超时停止、`java.ajaxAll` 参数处理、Cookie 文件不变不写、JS 桥/规则 URL 响应体 8MB 上限、导入读取移出主线程等）。**这类合并冲突解决出错会造成静默行为回归，编译不报错。**

**建议**（与 Claude 版一致，补充验收约束）：

1. 尽快在单独分支分批合并：先规则引擎与 JS 桥 → 书源核心 → RSS → 应用与阅读器；每批解决后跑对应阶段自动回归（S4 共享运行时 → S5 浏览 → S6 网页媒体），不要攒到发布前。
2. `Account/` 两个文件保持删除，但先核对上游改动中没有需要保留的修复。
3. 合并后复查 `java.ajaxAll`、正则超时、响应体上限与 fork 在 RSS 运行时中已有的限制是否重复或冲突。
4. 五语言 strings 合并后跑 `ruby scripts/check_localizations.rb`。

### P0-2（高）RSS 深链进书源导入器（两次审查提出，未修）

**证据链（已重新核对当前代码）**：

- `yuedu_appApp.onOpenURL`：文件走 drainer、`module` 走模块链接，**其余一律** `bookSourceDeepLinkHandler.handle(url:)`。
- `BookSourceImportDeepLink.target`：scheme 对且 host 为 `import` 时，不论路径 `auto`/`bookSource`/`rssSource` 一律返回 `.sources`。
- `BookSourceDeepLinkHandler.performImport`：`URLSession.shared.data(from:)` 下载（**无大小上限**）后只调 `BookSourceStore.parseForImport`，无 RSS 分支。
- 恶化点：`BookSource` 解码用 `safeString` 默认值，RSS JSON 会**解码「成功」**，产出空 `bookSourceName`/`bookSourceUrl` 的条目；`BookSourceImportCoordinator` 不过滤空 URL，用户可在确认页把空书源导入库。静默垃圾数据比直接报错更糟。

**建议**：下载后先经 `SharedImportPayloadClassifier` 分类（RSS 判定已就绪），命中 `rssLegadoJSON` 转交 `RSSImportService` 预览流；下载改用 `RSSImportService.download` 的限额版本（含重定向策略）。改动集中在 `BookSourceDeepLinkHandler` 一处。

**验收**：同一份订阅源 JSON 经文件、分享、深链三个入口导入，均出现 RSS 导入预览，书源库数量不变。

### P1-1（中高）S8 口径：自动回归通过 ≠ 阶段通过

`s8-acceptance.md` 明确写「S8 整体尚未通过」：R265/R267 真实 iframe 播放转人工 #58；受限登录、iOS 17、真实 WebDAV、正式签名/iCloud/App Group、真实账号登录、DRM、人工 VoiceOver 未验；R146 图片为外部证书链前置条件（SSL -9814）；#77 音频间歇停钟根因未定、转监控。

**建议**：发布前把 S8 收成一张清单——「发布门禁（必须过）」与「已知风险（带重开条件）」分开。iframe 与受限登录是 RSS 网页类源的核心路径，至少各跑通一个真实源后再宣布行为对齐完成。

### P1-2（中）导入校验比 Legado 严

**两侧源码对照确认**：

- fork `LegadoSourceJSONParser.validateFields`：字符串字段遇非 `String` 抛 `invalidFormat`；整数字段要求精确整数（1.5 被拒）。
- Legado `GsonExtensions.kt`：`StringJsonDeserializer` 把任意 JSON 转字符串（对象→`json.toString()`）；`IntJsonDeserializer` 数字取 `toInt()`（1.5→1），非数字回默认值。

按代码推断，`header` 写成对象、`articleStyle` 写成 `"1"`、`customOrder` 写成 `1.5` 的源在 Legado 可导入、在 fork 被拒（未在 Android 实测）。fork 自有 307 包可全量往返，问题出在第三方源包。

**建议**：对齐 Legado 宽容语义，导入预览标注「已修正 N 个字段」；仅缺 `sourceUrl` 才拒绝。注意同步更新 `validateFields` 相关测试，不要用「改测试期望」掩盖行为变化。

### P1-3（中，设计取舍）未注册旧 scheme

`Info.plist` 仅注册 `readerfork-dev`（已核实）。Safari/二维码/社区页面里的 `legado://import/...` 唤不起 fork。符合 ADR-0002 不争用原版注册的决策，**建议保留**，并在 RSS 导入页补「粘贴链接导入」入口（走 P0-2 修好后的统一分类路径）；只有确定不与原版同机安装时再考虑注册 `legado`。

### P1-4（中）`articleStyle` 0–4 未实现

`RSSFeedView` 只有单一 `RSSArticleRow` 布局。真实源包 50 个非 0（26 大图、19 两列网格、5 瀑布流），图片类源浏览体验差距明显。

**建议**：先做 2、3、4（网格/瀑布流），复用 `RSSImageService` 的请求头与解码；1（大图）实现简单可顺带。同时把列表缩略图从裸 `AsyncImage`（`RSSFeedView.swift:509-510`）切到 `RSSImageService`（P1-5 一并解决）。

### P1-6（中低）上游托管资源与 UA

已核实：`AozoraCatalogStore.swift:14` 目录清单取自 `https://yuedureader.com/catalogs/aozora/v1/manifest.json`；`RemoteLibraryHTTPClient.swift:26` UA 为 `Yuedu/<version> (iOS; +https://yuedureader.com/support)`。fork 用户请求会到上游服务器（IP 暴露、路径依赖），UA 与独立身份不符。

**建议**：清单自托管或随包打包；UA 换 fork 标识；同步更新引用这些字符串的测试。注意 S0 已确认「只读公共目录不属于被移除的账号后台」，本项是身份与隐私问题，不是功能缺陷。

### P1-7（中低）约 30 个 `java.*` 函数无对应实现

按名称检索缺口集中在压缩包、文件与缓存、字体反爬及少量运行时辅助函数。文件类 API 在 iOS 沙箱多半不该做；本期产品边界已排除扩大范围。**接受 Claude 版建议**：用真实源包做静态扫描，统计实际引用后再决定是否补压缩包/字体反爬，不按数量清单盲目对齐。

### P2 组（低/信息）

- **P2-1 `didSet` 全量撤销**：`RSSStore.swift:9-16` 任何 `sources`/`folders` 写入（含后台刷新回写 `resolvedFeedURL`）都 `configurationRevision++` 并 `invalidateRuntimes()` 全部源。后台写回可让另一源的前台在途请求票据过期、结果被静默丢弃。安全但浪费且有可感知取消。已有按源 `invalidateRuntimes(for:)`，可改按源修订号；先写并发测试再改。
- **P2-2 备份脱敏范围**：`RSSBackupCodec.swift:49-55` 仅当 `header` 以 `{` 开头时过滤 cookie/authorization 等；`@js:` 形式 header、URL query 令牌、`jsLib`/`loginUi` 内凭据原样入备份。`variable` 已置 nil。建议文档明示「备份可能含凭据」或提供不含认证信息的导出开关；WebDAV 是否强制 HTTPS 未核对。
- **P2-3 导入下载**：`RSSImportService.swift` 逐字节 `for try await byte in stream`（8MB×32 文档，改按块读取）；`validURL` 不拦 localhost/内网，嵌套 `sourceUrls` 可指向私有地址（对包内容展开的嵌套 URL 拒绝私有地址；顶层用户主动粘贴的可放宽）。
- **P2-4 残留文件**：`.firebaserc`、`firebase.json`、`firestore.rules`、`firestore.indexes.json`、`storage.rules`、`functions/`、`.github/workflows/aozora-catalog.yml` 均在。对 fork 是死代码，建议删除或归档；workflow 带 `contents: write` 且引用上游地址，优先处理。
- **P2-5 字段未读**：`enableReadRecord`（用户包 0 个源设置，影响为零）、`sourceComment`（Legado 在源详情展示，fork 无展示点）。
- **P2-6 分页停止条件**：fork 用整页 `isSubset` 判重复，Legado 用「新批次首尾已在库即停」。部分重叠时 fork 多翻一页，非缺陷，建议写入「与 Legado 的差异」文档。

## 4. 做得好的地方（两版一致，不再重复展开）

1. 请求票据与撤销：源 ID+配置修订+owner 标识，登录变化即时停止媒体会话。
2. `RSSWebActionRouter` 权限分级：sourceRule/page/attachment 三级，跨 origin/跨家族强制确认，URL 字面量化防模板注入。
3. WKWebView 加固：nonPersistent 数据空间、主框架与 `securityOrigin` 校验、前台要求、跨源导航拦截。
4. `RSSMediaResourceSession`：仅 loopback、双 UUID 能力路径、只服务已准备资源、HLS 改写拒绝 SAMPLE-AES/非 identity KEYFORMAT、连接与请求上限、登录变化即关闭。比上游 `HeaderedMediaAsset` 的非公开键方案更稳妥。
5. WebDAV 备份：manifest 最后上传作提交标记、SHA-256 逐文件校验、空间预算、journal 回滚、回滚失败保留副本。
6. 备份与日志脱敏、CI 保守（手动触发、按提交哈希固定依赖、真实源包未入库）、阶段文档诚实。
7. 代码静态面干净：RSS 模块无 `try!`/`fatalError`/主线程同步等待；唯一 `Task.sleep` 是 loopback 输入超时（有注释）；本地化检查与 `git diff --check` 本次实测通过。

## 5. 处理顺序建议

1. **P0-1 上游合并**：单独分支分批解决，每批跑对应 RSS 回归；这是其余改动的前置，避免在漂移的底座上继续堆功能。
2. **P0-2 深链分流** + 下载限额 + 三入口一致性测试；顺带完成 P1-3 的「粘贴链接导入」入口与 P2-3 的两个小修。
3. **P1-2 校验宽容化**，预览标注修正字段数。
4. **P1-4/P1-5**：`articleStyle` 2、3、4 布局 + 列表缩略图接 `RSSImageService`，一次改完列表展示层。
5. **P1-1**：S8 拆「门禁清单 + 已知风险清单」；至少一个真实 iframe 源与一个受限登录源跑通。
6. **P1-6**：上游资源与 UA 替换。
7. **P2 组**：P2-1 先写并发测试再改；P2-2 文档/开关；P2-4 清理；P1-7 按需；P2-6 记录差异。
