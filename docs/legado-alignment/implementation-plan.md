# RSS 对齐实施计划

> 依据：[最终方案 v2.0](development-plan.md)。Q1–Q13 与整体执行已确认；根目录 AGENTS.md 已生成。按 [ADR-0004](../adr/0004-remove-google-and-billing.md) 移除 Google/Firebase 及收费体系，保留 iCloud/WebDAV。WebDAV 首期对齐备份机制，不做 Android 整包互通。
> 本计划是工作依赖和验收合同，不是完成报告。只有执行过的测试可以登记为通过。

## 1. 执行规则

- 一次只有一个实施阶段在进行；每个阶段内部先建立可重复反馈，再修改，最后跑最小相关回归。
- 不修改原始源包，不执行未经隔离的源脚本；代表源联网与本地合成测试分开。
- 仅按现有固定 commit 开发，不自动 pull 最新，不同时迁移 Swift 语言模式、架构或依赖版本。
- 用户已授权逐阶段提交：阶段验收通过后用中文 commit，再进入下一阶段；未通过不提交为完成。不自动 push/release，不改签名账号或真实云配置，不擅自重跑昂贵云构建。
- 已有未跟踪 `.codegraph/`、文档、源包均保留，不清工作区；不删除模拟器或现有 App 数据。
- 不跳过编译/测试阻碍去堆后续实现。阻碍单独登记，已完成的局部工作与未完成阶段分开说明。
- 测试通过的证据在代码、环境和结论不变时复用，不无理由重复全量测试或 clean。

## 2. 依赖顺序

```text
S0 独立本地构建与基线
 └─ S1 固定输入合同与媒体技术验证
     └─ S2 导入和源配置保真
         └─ S3 条目身份与状态基础
             └─ S4 RSS 共享运行能力接入
                 └─ S5 打开优先级、分类搜索与分页
                     └─ S6 规则网页、图片与媒体闭环
                         └─ S7 独立入口、源管理与可视化诊断
                             └─ S8 分层实源与发布验收
```

S1 的媒体结论只约束 S6 的资源实现，不要求 S2 等数据工作等到所有媒体都可播放；若 PoC 对某类能力失败，明确记录受限或提出方案变更，不能静默吞掉。

## S0：独立本地构建与基线

**目的：** 在不连接原版账号/云服务、不提供原版 Firebase 配置的条件下启动测试 App，并能运行最小 RSS 回归。

工作：

1. 读取实际构建设置、依赖解析状态、App/扩展资源和启动路径，最小命令复现当前构建/启动阻碍。已知缺 GoogleService-Info.plist，但不假定这是唯一错误。
2. 分批移除 Google/Firebase 的真实调用链：先把诊断改为本地记录/导出，再移除账号、Firestore/网关同步与反馈、StoreKit/会员/Pro 控制，最后清理 SDK 产品、资源及构建脚本。保留本地通知、MetricKit、书源网站登录和用户自行配置的外部服务；不做成功空实现或伪造凭据。
3. 开发测试使用临时独立身份：显示名 `Reader Fork Dev`，主 App Bundle Identifier `dev.denis.readerfork.dev`；扩展/App Group/共享导入等使用对应独立命名空间或在该配置明确禁用。该身份不作为正式发布品牌。
4. 全 App 移除购买/会员入口和限制，已有本地能力可用；清理失效调用方和专属测试，用新的本地行为测试替代。保留 iCloud/WebDAV，其不可用不阻止本地阅读，不复用原版容器/凭据。
5. 核验无 Firebase/原版账号网关、StoreKit 购买或权益请求及残留 Google SDK 产品，再采集 RSS 现状测试基线。公共书库原有的 Storefront 地区可用性查询保留，它不是收费或账号准入，不在本轮静默改变地区支持策略。不能仅凭启动成功认为移除完成；每批局部验证不代替最后的 App 构建和冷启动。

重点入口：`Yuedu-Reader.xcodeproj`、`Targets/Yuedu/SharedApp/yuedu_appApp.swift`、应用依赖/服务初始化、Account/Subscription/TestFlight/同步入口。先追实际调用再确定最小编辑点。

验证：项目/配置解析；最小 App 构建及冷启动；`LegadoRSSCompatTests`、`RSSStoreTests`、`RSSBackgroundRefreshTests`、`RSSLinkRouteTests` 的适用基线。优先通过测试构建获取编译证据，不另开 DerivedData。

回滚：配置编辑前备份；每批移除保留可审查 diff，可逐批撤回，不触碰原版数据，不修改真实云端。失败时保留完整脱敏构建日志，不能进入 S2。

## S1：固定输入合同与媒体技术验证

**目的：** 给后续每个行为差异建立可重复的输入/输出，不靠网站恰好可用判断改动。

工作：

- 复用既有测试框架，新增少量去敏或自建 fixture：singleUrl 混合配置、动态分类、文章变量、分页、type=1/2、HTML video/iframe/脚本、登录检查和源更新。
- 记录原始样本哈希和全包静态审计；不将原始 4 MB 级源包无筛选搬进测试 target。
- 按已有 `SourceScriptHost`、规则引擎和网络接口选择内部测试 seam；不创建生产第二引擎。
- 用本地测试资源验证普通图片/HTML媒体、AVPlayer、受控网页三类资源路径。先测试现有能力，再比较确有必要的自定义 scheme/loopback。
- 检查 HLS playlist/segment/key、Range/206/416、HEAD、Cookie/Referer、重定向、JS动态地址、取消与关闭。测试资源使用合成数据或有明确许可的样本。

验证：离线用例对当前行为的期望与实际差异明确；媒体 PoC 每个场景有真实观察结果，不能把理论当通过。

交付：`docs/legado-alignment/validation.md`，记录固定输入、环境、命令、结果/待验证。源脚本真实联网仍未自动启动。

回滚：PoC 与 fixture 不改变生产路由。新增依赖、额外播放器或大范围 WebView 方案不在授权内，必须另说明再决策。

## S2：导入和源配置保真

**目的：** 源配置不丢失，更新不换身份；导入和首次刷新结果清楚。

工作：

- 数组、单对象、sourceUrls 展开；循环/层级/数量/响应大小限制和逐项错误。
- 原始 sourceKey 与求值 URL 分离；缺名称使用安全派生显示名。
- 新增/更新/跳过的比较与确认；保留本地 source.id、用户分组、启用等字段的规则明确。
- 承载基准所需源字段，保留/披露未知字段；验证编码与导出，不把“字段有了”列作可用功能。
- 把本地/远程导入收敛为一个用例；保存成功不受首次抓取失败影响。刷新复用已有服务适用能力，可取消，不自动打开登录网页。

入口：`LegadoSourceJSONParser.swift`、`RSSModels.swift`、`RSSStore.swift`、`RSSListView.swift`、`RSSFeedRefreshService.swift`；确有业务复用才抽取导入用例模块。

验证：导入/导出、更新幂等、重复key、不标准URL、缺名、包递归、网络失败报告、普通OPML不回归；全包 307 项能够被识别并明确报告字段处理情况。

回滚：只涉及配置和导入，不与条目主键迁移或媒体代理绑在同次变更。

## S3：条目身份与状态基础

**目的：** 新 Fork 从首次发布使用正确条目身份，已读/收藏/播放不串源。

工作：

- 定义 source、分类/查询、原始条目key、稳定文章/附件ID，页码/临时签名URL不得成为状态唯一key。
- 记录格式版本；配置、正文/附件、状态分离；进度有单一 owner。
- 为文章级变量、分类和附件持久化提供数据模型；按实际需要适配现有 RSSStore，不新增同类 store。
- 覆盖应用内所有 articleID 消费者：文章、智能列表、探索入口、通知、状态动作。首期不接原版 Firestore，也不迁移原版多文件历史。
- 明确删除/更新/重导语义、孤立状态处理及 Fork 自身升级兼容；异步旧数据不得在删除后复活。
- 为 WebDAV 定义版本化 RSS 配置/状态快照与校验恢复边界；包含稳定身份，不把 Cookie/登录凭据或临时签名 URL 当作可直接恢复的登录状态。

验证：不同源同GUID、同源不同分类同链接、签名URL变化、收藏/媒体进度重启恢复、通知入口、删除与晚到响应、格式版本和不变不写。保留 `performRefreshBatch` 行为测试。

回滚：版本化的新数据格式在独立空间验证；已存在任何真实 Fork 发布数据后，不可通过“清数据”回滚，必须做显式兼容迁移。

## S4：RSS 共享运行能力接入

**目的：** 分类→列表→条目→正文的源上下文和回调真实生效。

工作：

- 以源身份和配置修订管理执行生命周期，绑定源配置、jsLib、请求头与持久变量。
- 源级、流程级、文章级状态分开；每次执行设置/清理当前上下文，同源并发不得串值。
- 接通 `getString(rule,mContent)`、getElements、setContent、put/get 等规则回调；不只注册函数名。
- 统一适用的请求构建/返回值、headers、encoding、loginCheckJs、Cookie、每源限流；共享实现仍服务书源，不另起平行实现。
- 配置更新、登录状态变化、删除和取消让相关状态/请求正确失效；后台需要UI时返回可辨识结果。

验证：源隔离、同源状态连续、文章变量读写、URL与规则阶段不同bindings、异常响应登录检查、CookieJar开关精确语义、重定向认证边界、JS内请求限流、取消/晚到结果。复用 `LegadoRuntimeContractTests`、`BookSourceSessionQueueTests` 等适用回归。

回滚：RSS 接入可独立撤回；共享代码的任何书源回归必须在本阶段修复，不留下“以后再修”。

## S5：打开优先级、分类搜索与分页

**目的：** 入口和后续页面与 Android 语义一致，不止首页有效。

工作：

- singleUrl 优先，计算动态启动 URL；否则 startHtml/分类列表。
- description 内容优先，再正文规则/原网页；不误用普通全文长度启发式替换规则网页。
- 分类与远程搜索作用域、变量和请求metadata正确隔离。
- PAGE/nextURL 的列表分页、nextContentUrl 正文分页，按基准处理相对URL/redirectURL。
- requestId/generation、防重复/循环、成功后推进页码、失败重试原页、多链接合并顺序、最大预算与部分结果标记。
- type=1/2 不使用文本正文拼接合同。

验证：6个已知singleUrl分支差异的去敏fixture；分类切换、搜索切换、刷新vs下一页、旧请求返回、失败后重试、重复页、空页、达到预算；普通Feed的304和缓存失效。

回滚：路由/分页改变在独立状态模型之上，禁止以清空所有源缓存作为恢复手段。

## S6：规则网页、图片与媒体闭环

**目的：** 页面/媒体内容正确显示，必要认证、状态与资源释放一致。

工作：

- 普通安全文章与受控规则网页使用明确的展示合同，共用适用模块，不把失败当成偷偷扩大权限的触发条件。
- 按源配置执行样式、baseURL、enableJs、start*、preloadJs/injectJs、跳转和黑白名单；桥接验证来源/frame/能力，不提供任意系统访问。
- 图片解码、懒加载地址、附件解析结果持久化；复用图片查看/固定页能力。
- type=2 与媒体附件接现有播放能力，补稳定条目/附件进度适配；音频/视频切换正确处理现有播放协调。
- 采用 S1 有证据的资源方案验证 headers、Cookie、Range、HLS、签名过期、加载错误和取消。
- 支持的网页播放器按源正常运行；DASH/DRM和不可映射API明确受限，不新增播放器依赖。

验证：合成type=1/2、type=0脚本/iframe/HTML5媒体；媒体服务器测试；页面打开/关闭、前后台、播放竞争、重启进度、过期URL、跨域认证不得泄漏；至少一轮真机端到端媒体验证。

回滚：资源适配和网页能力有明确开关/配置边界，但关闭后的受限行为必须披露。不能让验证失败变成“自动打开原文即成功”。

## S7：独立入口、源管理与可视化诊断

**目的：** 用户可找到订阅、维护源并理解失败，而不是依赖 Android 调试。

工作：

- 默认五Tab：探索/书架/订阅/资源库/设置；恢复独立订阅root，资源库链接仍可达同一业务模块。
- 搜索从书架/探索清晰入口进入，保留脚本触发与原有搜索能力；不建立第二套搜索。
- 源列表/分组主界面、分类源内展示；源编辑、变量/登录、导入更新、错误报告。
- 可视化调试复用S4的事件，展示脱敏请求/规则/分页/资源结果，不再执行独立调试解析路径。
- 同步 RootTab 定制、根标题白名单、相关设计文档/skill和测试；推入时inline；本地化、VoiceOver、权限拒绝、iOS17弹层时序。
- 在已有 WebDAV 入口补分类选择、版本化备份与历史恢复；加入 S3 定义的 RSS 配置/状态。验证损坏包、路径越界、空间不足、取消和中断时原数据完整。不做 Android 整包互通或全媒体缓存打包。

验证：新装默认Tab，搜索可达，资源库与Tab状态一致，源添加/更新/登录/取消，iPhone/iPad及Dynamic Type、VoiceOver，`ruby scripts/check_localizations.rb` 和必要UI测试。

回滚：新入口可独立恢复旧布局，但不删除源/文章；不能因UI更改改变数据身份。

## S8：分层实源与发布验收

**目的：** 明确实际完成与受限范围，而不是宣称307个全部可用。

- 再核对307个源导入/字段报告，不重复未经改变的离线证据。
- 根据前述静态特征挑选代表源，涵盖文本、图片、HTML视频、脚本/iframe、登录、分页；入选前检查脚本副作用，在受限请求和临时存储环境中低并发、有限请求验证，不把整个原包直接加载后自动执行。
- 实际网站不可达、账号要求、平台限制与程序缺陷分开；需要个人凭据的源不擅自测试，使用合成登录fixture并标真实场景待验证。
- 以当前原生能力实测媒体，不承诺所有格式；未验证设备/系统不标通过。
- 对307源规模的合成场景记录请求、内存、主线程及写盘次数，与基线比较；不做未经测量的优化。
- 汇总代码、测试、受限项、剩余风险；签名/正式品牌/发布另获确认，任务完成不等于已发布。

发布门槛：相关回归实际通过、代表性原始失败闭环、iOS17和真机所需验证有证据；否则阶段保持未完成并记录阻碍。

## 3. 测试命令惯例

按运行时工具链和目标生成命令，不硬编码设备名/系统/Xcode路径。以下是模板，实际命令与结果进入 validation.md：

```bash
bash scripts/sim.sh doctor
export DEVELOPER_DIR="$(bash scripts/sim.sh xcode)"
export YUEDU_DEST="$(bash scripts/sim.sh dest)"
bash scripts/xctest.sh -- -only-testing:'yuedu appTests/LegadoRSSCompatTests'
```

本地独立 scheme 确定后，通过脚本已有 `YUEDU_SCHEME` 配置传入。阶段新增测试按真实文件/函数筛选；不要以0个测试的成功退出作为通过，也不要以仅一类框架的中途结果提前判定整个测试run。

## 3.1 逐阶段自动验收关卡

以下是必须落实的验收合同，不代表对应测试已经全部存在或通过。每阶段先把具体测试名称、固定输入和失败条件写清楚；实现时运行最小相关回归，阶段收尾再运行该阶段适用测试集合。

| 阶段 | 主要自动验收 | 不能由这些测试替代的验证 |
| --- | --- | --- |
| S0 | 工程解析、App/扩展编译、独立身份与冷启动 UI 测试、无原版服务依赖检查、现有 RSS 行为基线 | 自有签名、真实 iCloud 容器/设备间同步 |
| S1 | 合成 fixture 与本地资源服务器、请求/解析和媒体 PoC 的可断言结果 | 真机媒体链与系统行为差异 |
| S2 | 导入/导出往返、幂等更新、字段保真、递归/畸形包/网络错误 | 用户私有登录配置的真实可用性 |
| S3 | 持久化后重建 store、身份隔离、删除与晚到响应、不变不写、备份快照与恢复 | 实际升级设备与系统终止条件抽查 |
| S4 | 执行上下文、变量隔离、认证传播、Cookie、并发/取消、共享书源回归 | 需要人参与的登录/验证码 |
| S5 | 打开优先级、分类/搜索切换、列表/正文分页、重复页/重试/取消 | 少量代表站点的端到端差异 |
| S6 | 本地阶段通过 | 规则网页/请求/Cookie/图片/动作/登录/媒体/cacheFirst/签名过期重算/SVG/explore/AX：双设备各S5 268项 + S6 97项零失败零跳过；真机iPhone 17 Pro 92项通过，用户确认画面和声音正常。iOS17/DRM/真人登录/真实源移交S8，见[S6记录](s6-rule-web.md) |
| S7 | 导航/导入/管理 UI 测试、本地化/可访问性检查、WebDAV备份恢复与故障注入 | VoiceOver实际使用、Dynamic Type视觉检查、真实WebDAV服务 |
| S8 | 分层代表源与回归重跑、请求/写盘/内存/主线程性能采集 | 最低iOS与真机发布抽查、需私人账号的场景 |

规则：

- 用 `scripts/xctest.sh` 串行运行 iOS 测试；它检查最终结论和非零测试数量。宿主子集测试只能证明该子集，不代表 App 构建或端到端通过。
- 静态依赖/字符串检查是补充防回归，不代替请求、存储、UI或媒体实际行为。UI测试须断言操作后的结果，不只断言页面存在。
- 自动测试失败、0项、跳过关键场景或中途退出均不放行；没有测试覆盖的需求不能记为已完成。
- 每阶段在 `validation.md` 记录命令、环境、测试数量、最终结果、日志/xcresult路径和未验证项。硬件/账号条件不足则单列未通过的验收门槛，不把它改写成自动测试成功。
- 当前没有承诺已建立远端CI。先在本机形成可复现命令；签名、CI机器或凭据接入另行确认，不上传原始源包或私有日志。
