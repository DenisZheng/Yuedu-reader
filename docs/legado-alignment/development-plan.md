## 3. 首期完成定义

### 必须完成

1. 数组、单源对象、sourceUrls 集合和文件/远程地址导入；可比较更新、保留原始配置、逐源结果。
2. 原生 RSS/Atom/JSON Feed 与 Legado 规则抓取两条内容路径均可用，公共请求和 JS 能力只维护一套。
3. 源配置、jsLib、登录检查、变量、规则回调、Cookie 与每源限流在完整流程中生效。
4. singleUrl/动态启动 URL/startHtml/分类/description/正文规则的打开和内容优先级对齐。
5. 分类、源内搜索、列表分页、正文分页、状态保留和取消/失败处理闭环。
6. 普通 Feed 附件、图片型/视频型条目、网页内媒体、图片解码、规则网页注入和跳转交互。
7. 阅读、收藏、媒体进度以稳定条目身份保存；刷新、删除、重导及 Fork 升级有明确行为。
8. 独立订阅入口、源管理、必要规则编辑和阶段诊断；五语言、VoiceOver、iPhone/iPad 基本可用性。
9. 无 Google/Firebase 或收费依赖的独立构建，保留本地诊断、iCloud 和 WebDAV。按下述合同补齐 RSS 配置/状态的备份恢复。

### 不等于完成

导入显示成功、列表有首页、存在播放器、字段被保存、能打开原文、只有源码字符串测试通过，均不能代替业务行为验收。

### 允许但必须披露的受限项

DASH/DRM、平台不支持的媒体编码、无法映射的 Android/Java API、需要真实私人账号且未提供测试账号的场景，以及未实测的源。为每项记录“确定不支持/需要前台交互/未验证/站点暂不可达”，不得混成统一失败或成功。

## 4. 数据与状态合同

首期是独立全新数据空间，不做原版 iOS/Android 书架、云端、通知历史的整体迁移。导入源配置不等于迁移原版状态。但 Fork 自身从首次发布起必须具有可版本化、可升级的数据格式。

### 4.1 分开四种身份

- 原始 sourceKey：保留 Legado sourceUrl 的完整语义；不为了去重去掉 `#`、查询、模板或 URL options。
- 本地来源身份：导入更新时保持稳定；不能因为远程配置带新 UUID 就丢掉本地关联。
- 分类/搜索作用域：源内分类和搜索查询不能互相覆盖；页码不属于条目身份。
- 条目/附件身份：用来源与内容锚点区分同 GUID/同链接；媒体签名 URL 不是播放进度的唯一 key。

结构校验不强制 sourceKey 本身就是可请求 HTTP URL。实际发请求前再验证求值后的 URL、协议和权限。缺名称用派生显示名，不必篡改源配置来生成名称。

### 4.2 状态唯一归属

RSSStore 继续作为 RSS 持久数据 owner，不新增重复的 RSSSourceStore。正文/附件属于内容；已读、收藏、阅读位置/媒体进度属于状态，播放器不维护另一份可冲突的权威状态。

当前页、下一页、是否还有内容之间必须明确派生关系，不能建立三份互相矛盾的事实。全量刷新不改动的数据不落盘，保留现有 performRefreshBatch 合并写入能力。

### 4.3 配置保真

承载当前基准已知字段，包括 type、nextContentUrl、searchUrl、preloadJs、startHtml/startStyle/startJs、coverDecodeJs、页面设置和媒体所需字段。保留字段和运行字段分开记录；遇未知字段可保留扩展数据或给出明确导入报告，不能静默丢失后宣称无损兼容。

导入、更新、修改源、重新抓取和导出都要验证。源修订、登录变化或删除后，旧请求不得写回新配置的结果。

### 4.4 iCloud 与 WebDAV

- 保留现有 iCloud 能力，使用 Fork 自己的容器与签名；iCloud 不可用不能阻止本地启动或阅读。不承诺未实测的跨设备 RSS 同步。
- WebDAV 采用 Android 式分类选择、版本化备份包和历史备份恢复，先保证 Fork 自身数据恢复；不实现 Android 整包导入/导出。
- 保留现有书源、书架元数据、替换规则备份，加入 RSS 源/分组/分类、收藏、已读与阅读/播放进度；iOS 专属字段使用自己的版本化格式。缓存正文及音视频不默认打包。
- Cookie、登录信息、源变量等敏感运行数据默认排除；若提供显式可选备份，必须有加密和恢复边界验证，不能明文导出。WebDAV/iCloud 账号凭据不随包导出。
- 先验证版本、条目数量、总大小、路径及校验和，再按现有数据 owner 恢复；损坏、空间不足、取消或中断不能破坏当前数据，失败不能标为成功。具体原子提交方式在 S3 的持久化模型确定后实现。

## 5. 运行时与请求合同

### 5.1 复用而非复制

复用/按真实需要提取现有 SourceScriptHost、BookSourceSession/ModernParserBridge 的共享能力、AnalyzeUrl、ModernRuleEngine、CookieStore、限流和日志。RSS 可以有自己的流程适配层，但不另写 URL options 解析器、平行缓存或无状态临时 JSContext 系统。

JS 引擎只在需要时创建。同源状态可连续，不同源隔离；每次请求/文章的 bindings 不能泄漏到其他执行。主线程不得等待阻塞 JS/网络，异步任务具备取消、优先级和执行额度约束。

### 5.2 上下文与变量

URL 脚本、提取规则、源级脚本和页面动作的 java 对象/变量绑定不同，分别对照基准。验证 `java.getString(rule, mContent)`、getElements、setContent、put/get、source 自定义变量与 cache，而不只检查函数是否存在。

分类→列表→条目→正文保留正确上下文。源级持久变量、流程变量和文章变量分别归属，不全部装进同一字典。

### 5.3 网络与登录

- 覆盖 URL 模板、GET/POST/HEAD、headers/body、字符集、最终 URL、状态和错误响应。
- 源 header 可以是脚本；列表、正文、图片和媒体使用适用的请求上下文。
- 登录检查的返回值与状态写回影响同一流程后续请求；提供前台登录入口和清晰的需交互状态。
- enabledCookieJar 控制自动管理，不表示禁止所有显式/已保存 Cookie。定义 Cookie 的域/path/过期及 WebView 同步，不无意跨源/跨域传播身份。
- 不无条件把私有认证头加到外链、CDN 和所有重定向；资源请求有目标作用域。
- 普通 Feed 保留 ETag/Last-Modified/304 合同；配置、认证或实际请求身份变化时正确失效。
- concurrentRate 与任务取消均覆盖 JS 内请求；等待用户交互与网络超时分别处理。

### 5.4 导入和刷新分开

Import→结构/能力校验→确认保存→可取消的首次刷新。保存成功与刷新失败分别报告；离线或需登录的源仍可保存。sourceUrls 展开限制数量、层级、响应大小并防循环。批量导入不自动弹出大量登录页或执行高影响动作。

复用 RSSFeedRefreshService 的适用流程，而不是在 View 新增请求→解析→存储链。后台不运行需要用户 UI 的步骤，记录需前台继续；本轮不增加通用后台任务。

## 6. RSS 浏览与网页合同

### 打开源

1. singleUrl=true：按基准解析 sortUrl/脚本得到启动 URL，优先单页。
2. 否则尝试 startHtml；有启动内容则展示启动页。
3. 否则进入分类/文章列表。

### 打开网页条目

已有 description 内容优先，其次 ruleContent，最后原网页；无缓存文章的历史入口按可恢复的数据打开。不能用普通全文提取的长度启发式替换掉规则生成的交互 HTML。

### 两种展示模式

- 标准 Feed 的普通文章继续安全清理，保留合规图片和静态媒体。
- Legado 规则网页按源配置运行；支持 enableJs、base URL、style、启动页脚本、preloadJs、injectJs、跳转和资源过滤。源配置与网页桥接之间有最小权限限制，不赋予任意文件/系统访问。

对受控网页的支持是明确主路径，不是抓取失败后偷偷升级 WebView 的 fallback。页面外部导航、剪贴板、下载/导入等动作由对应授权和确认约束。

## 7. 分页、分类与源内搜索

列表 ruleNextPage 与正文 nextContentUrl 分开；PAGE 特殊值、相对 URL、重定向基址按 fixture 对照 Android，不统一猜测。

- 成功提交后推进页码；失败保持同页重试目标。
- requestId/generation 拒绝晚到结果；刷新、换分类/搜索、删除源均不能串写。
- 重复/循环 URL、空页和无新增条目可区分；有最大页数/总大小/执行预算，达到预算必须报告截断原因。
- 多链接正文按基准顺序合并，取消/部分失败明确处理。
- 图片/视频条目保持单媒体结果合同，不将多 URL 换行拼接后交给播放器。
- 分类内容与搜索结果的缓存作用域明确，但共用现有持久化 owner，不再建第二个并行缓存层。

## 8. 媒体与资源访问

### 图片和附件

保留 RSS/Atom/JSON Feed 解析到的附件、MIME/尺寸/时长等信息；HTML 懒加载图片先规范化必要来源再显示。RSS 图片按 coverDecodeJs 解码，不能只有 URL；全屏查看优先复用现有固定页/图片能力，包含缩放、保存/分享、失败和权限拒绝。

### 原生媒体

RSS type=2 与 Feed 媒体附件通过稳定条目/附件身份连接现有 VideoPlayerView/VideoPlaybackController 或音频播放能力；需要最小状态读写适配，不能仅按临时播放 URL 保存进度，也不创建另一套播放服务。

处理 MP4/HLS、Referer/Cookie、Range、签名过期、播放中断与恢复。现有播放实现使用的非公开 Header key 不能作为未验证保证。DASH/DRM 等明确受限，不引入新播放器依赖。

### 网页媒体和技术验证关卡

type=0 的 HTML video/iframe/脚本播放器是首期重点。先分别验证静态媒体、原生播放、规则网页三种资源路线，再选择最小实现。

WKURLSchemeHandler 不可直接接管原生 https；不把 URLProtocol 当 WebKit 通用拦截。自定义 scheme 或 loopback 都仅是待验证候选，不提前选定。验证 CORS/CSP/origin、动态 JS URL、重定向、Cookie、嵌套 playlist/segment/key、HEAD、200/206/416、取消/释放；如新增代理，明确本机监听、访问凭据与目标限制，不能变成任意转发服务。

普通文章不因规则网页能力获得无限权限；无法支持的媒体错误明确显示，不用“打开原文”掩盖主路径失败。

## 9. 导航、管理与诊断

默认导航固定为「探索｜书架｜订阅｜资源库｜设置」。搜索功能通过书架/探索清晰入口保留；源脚本触发搜索仍可达。资源库的订阅链接与 Tab 使用同一数据和业务模块。

订阅首页以源列表/分组为主，分类进入源后展示；不继续让树形文件夹成为唯一内容入口，不照搬 Android 外观。原生 Tab/NavigationStack/List/菜单，使用设计 tokens，iOS 17 菜单到弹层按真实 dismiss 顺序。

新增 RSS Tab 根页面须同步更新根标题白名单、根 Tab 定制和测试约束；推入同模块时仍用 inline 标题。所有新增用户文案同步五个语言表，验证 VoiceOver、Dynamic Type 和 iPhone/iPad。

必要源编辑覆盖已支持字段、源登录、变量及导入更新；诊断从底层阶段开始具备，最后再补完整可视化调试页。日志展示脱敏的阶段、状态、规则、数量和分页轨迹；URL query、正文和错误也要脱敏，不能只处理头部。

## 10. 开发验证与发布门槛

### 分层验收

1. 全包静态/导入：307 个 RSS 字段、类型、导入导出；原始包保持不变。
2. 离线行为：去敏固定响应与合成 type=1/2、sourceUrls、缺名和异常数据，覆盖变量/分页/路由/状态。
3. 本地资源服务器：图片、HTML/脚本、媒体请求、认证和 Range；验证不依赖第三方稳定性。
4. 隔离代表源联网：按类别选源，限制请求量，无个人账号和自动高影响动作。
5. 设备验收：iPhone/iPad，最低 iOS 17 和当前可用版本；真机媒体能力不可由解析成功代替。

真机或 iOS 17 环境暂缺时，代码可以继续完成可验证部分，但相应发布门槛保持未通过。不得把平台未验证写成通过。

### 完成要求

相关测试实际运行并通过；新功能的原始失败模式得到覆盖；已读/收藏/位置在刷新和重启后正确；无未披露的丢字段、截断、fallback 或后台承诺；不破坏书源/媒体/搜索现有功能。每阶段记录变更、测试命令、结果、未验证项和回滚办法。

性能以 307 源静态包及多页 fixture 测基线，记录主线程耗时、峰值内存、请求数和写盘次数；不在测量前编造达标数字。验证工具优先 scripts/sim.sh、scripts/xctest.sh，动态解析 toolchain/destination，串行测试，不另开 DerivedData 绕过问题。
