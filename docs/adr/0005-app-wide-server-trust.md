# App可控制的连接采用兼容性服务器证书策略

用户在2026-11-14评审修复中明确接受上游「全 App 接受无效 TLS 证书」的选择，优先兼容 Legado 源站，而不再默认拒绝过期、自签名、不受信任根或主机名不匹配的服务器证书。此决策取代此前禁止证书绕过的约束；不降低TLS 1.2协议下限，也不授权自动擦除模拟器。

## 后果与边界

- App可控制的URLSession/WKWebView对server trust challenge使用服务器提供的证书；HTTP Basic/Digest和客户端证书等其他challenge仍使用系统默认处理。
- HTTPS仍加密传输，但不再可靠验证服务器身份。中间人可能读取或篡改登录、Cookie、AI服务和WebDAV凭据；跨域认证过滤、沙箱、网页消息校验、请求预算和取消规则保持不变，不能把这一例外扩展成关闭其他安全检查。
- 同一host每次启动只记录一次证书风险诊断。日志不包含原始host、URL、凭据或错误正文；离线检查已经提供的证书链，不额外请求证书/撤销信息。
- 系统自己控制的连接并不因此获得相同策略：CloudKit、AVFoundation直接播放HTTPS资源、没有可注入session的系统图片加载等仍可能拒绝无效证书。不得声称所有系统网络路径已绕过校验。
- R146历史`-1202 / SSL -9814`保留为旧策略下的失败证据。调整客户端策略不是修复站点证书链，也不构成图片已下载、解码或显示成功；须用批准的相同目标另行复验。
- 撤回时恢复系统server trust处理，并重验请求、网页和媒体；不安装CA、不改系统时间，不触碰用户数据或原始源包。
